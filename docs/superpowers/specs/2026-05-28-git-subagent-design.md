# Git Subagent Design

**Date:** 2026-05-28
**Status:** Approved

---

## Goal

Activate the git subagent and wire it into the end-to-end pipeline so that the planner can include git operations (branch, commit, amend, push) as part of a task. Additionally, expose git read tools to the reader subagent so it can use `git_status`, `git_diff`, `git_blame`, and related tools during code investigation.

---

## Approach

**Approach C — Derived files + structured commit message.**

- `filesToStage` is derived deterministically from `editorAppliedFiles` (which files the editor actually touched), not guessed by an LLM.
- Commit message is generated by one small structured LLM call (conventional commit format) using `plan.goal` and the list of edits applied.
- Branch name and push/amend flags come from `plan.gitStep` (new optional planner output field).
- The git subagent graph is a deterministic executor — not a free-form agent loop for write operations.
- Push always requires user approval via `interrupt()`. Everything else (branch creation, staging, committing, amending) runs automatically.

---

## Architecture Overview

```
Root graph (after):
  edit_intent
    → delegate_writer         ← captures editorAppliedFiles (fix: was returning {})
    → build_git_intent        ← NEW: derives filesToStage, calls LLM for commit msg
    → delegate_git            ← NEW: calls gitAgent.run(gitIntent), handles interrupt
    → END

Git subagent graph (uncommented + completed):
  START
    → initialize
    → execute_git_ops         ← NEW: deterministic sequential executor
        ↓ push=false
        → final → END
        ↓ push=true
        → push_approval       ← NEW: interrupt() for user confirmation
        → tools (git_push)
        → final → END
```

## PlannerOutputSchema Change

Add an optional `gitStep` field to `packages/shared/src/schemas/planner.ts`. Null means no git operations — the pipeline skips `build_git_intent` and `delegate_git` entirely (no-op).

```typescript
gitStep: z.object({
  branch: z.string().optional()
    .describe('Branch name to create before committing, e.g. "feature/add-faq-route". Omit to stay on current branch.'),
  push: z.boolean()
    .describe('Whether to push after committing. Always requires user approval.'),
  amend: z.boolean().default(false)
    .describe('Amend the last commit instead of creating a new one.'),
}).nullable().optional()
  .describe('Git operations to perform after edits. Null = no git step.')
```

The planner prompt gets a brief addition: when the user's request involves committing, branching, or pushing, set `gitStep`. When the task is code-only, leave it null.

## GitIntentSchema

New file: `packages/shared/src/schemas/git/intent.ts`

```typescript
export const GitOpResultSchema = z.object({
  op: z.string(),           // 'checkout_branch' | 'add' | 'commit' | 'amend' | 'push'
  status: z.enum(['ok', 'skipped', 'failed']),
  output: z.string(),
  error: z.string().optional(),
});

export const GitIntentSchema = z.object({
  filesToStage: z.array(z.string()),   // derived from editorAppliedFiles
  commitMessage: z.string(),           // generated by LLM
  branch: z.string().optional(),       // from plan.gitStep.branch
  push: z.boolean(),                   // from plan.gitStep.push
  amend: z.boolean().default(false),   // from plan.gitStep.amend
});

export type GitIntentType = z.infer<typeof GitIntentSchema>;
export type GitOpResult = z.infer<typeof GitOpResultSchema>;
```

## delegateWriterNode Fix

Currently `delegateWriterNode` ignores the editor's return value and returns `{}`, so the root graph has no knowledge of which files were applied. Fix: capture and surface `editorAppliedFiles`.

```typescript
// Before
await writerAgent.run({ ... });
return {};

// After
try {
  const result = await writerAgent.run({ ... });
  const editorAppliedFiles = (result.editResults ?? [])
    .filter(r => r.status === 'applied' || r.status === 'recovered')
    .map(r => r.file);
  return { editorAppliedFiles };
} catch (err) {
  const isInterrupt = err?.name === 'GraphInterrupt';
  if (!isInterrupt) throw err;
  // Editor paused for tool approval — editResults not yet available.
  // Fall back to editIntent.edits so buildGitIntentNode has something to work with.
  const editorAppliedFiles = state.editIntent?.edits.map(e => e.file) ?? [];
  debug('[delegateWriter] editor interrupted — using editIntent files as fallback');
  return { editorAppliedFiles };
}
```

Add `editorAppliedFiles: Annotation<string[]>` to `RootState`.

> **Edge case**: when the editor interrupts for tool approval, the root graph ends before the editor resumes. `buildGitIntentNode` runs with the fallback file list (editIntent planned files). `git add` on a file with no changes is a no-op, so this is safe.

## buildGitIntentNode

New file: `packages/agent/src/nodes/root/buildGitIntent.ts`

Logic:
1. If `state.plan?.gitStep` is null/undefined → return `{ gitIntent: null }` (no-op).
2. Derive `filesToStage = [...new Set(state.editorAppliedFiles)]`.
3. Call a small structured LLM for commit message:
   - System: `"Write a conventional commit message (feat/fix/refactor/chore/docs). One line, under 72 characters. Format: type(scope): description"`
   - Human: goal, files changed, edit actions (mode/action/file from `editIntent.edits`)
   - Output schema: `{ message: z.string() }`
4. Assemble and return `{ gitIntent: { filesToStage, commitMessage, branch, push, amend } }`.

Add `gitIntent: Annotation<GitIntentType | null>` to `RootState`.

## executeGitOps Node

New file: `packages/agent/src/nodes/sub/git/executeGitOps.ts`

Runs all operations sequentially in a single node (no loop — at most 4 steps):

1. **Branch** (conditional): if `gitIntent.branch` → `git_checkout_branch(branch)`. If branch already exists, record warning and continue on existing branch.
2. **Stage**: `git_add(filesToStage)`. Harmless if a file has no changes.
3. **Commit or Amend**: if `gitIntent.amend` → `git_amend(filesToStage, commitMessage?)`. Else → `git_commit(commitMessage)`. Skip if nothing was staged.
4. **Push gate**: if `gitIntent.push` → set `pendingToolCall = { tool: 'git_push', ... }` and return. Else → return with `pendingToolCall: null`.

Each step result is recorded in `gitOpResults[]`. Failures record the error but do not throw — the node continues and reports via final output.

### afterExecuteGitOps router

```typescript
export const afterExecuteGitOps = (state: GitStateType): 'push_approval' | 'final' =>
  state.pendingToolCall ? 'push_approval' : 'final';
```

## pushApprovalNode

New file: `packages/agent/src/nodes/sub/git/pushApproval.ts`

Mirrors `toolApprovalNode` in the editor:

```typescript
EventBus.emit('agent:tool_pending', {
  sessionId,
  tool: 'git_push',
  description: `Push branch "${branch ?? 'current'}" to origin`,
  commitMessage,  // shown in UI so user sees what they're pushing
});
interrupt();
```

Resumed via `agent:resume:git` event (new, added to `AppEvents`):

```typescript
// packages/shared/src/types/event.ts — add to AppEvents:
'agent:resume:git': { sessionId: string; decision: 'approve' | 'reject' | 'y' | 'n' };
```

### afterPushApproval router

```typescript
export const afterPushApproval = (state: GitStateType): 'tools' | 'final' =>
  state.toolApproved ? 'tools' : 'final';
```

If the user declines push, the commit stands — this is a safe partial outcome.

## New Write Tools

All in `packages/tools/src/tools/git/`.

### git_add (`add.ts`)
```
git add <file1> <file2> ...
schema: { files: z.array(z.string()) }
```
Always takes explicit files. Never `git add .`.

### git_commit (`commit.ts`)
```
git commit -m "<message>"
schema: { message: z.string() }
returns: commit hash on success
```

### git_amend (`amend.ts`)
```
git add <files> && git commit --amend [-m "<message>" | --no-edit]
schema: { files: z.array(z.string()), message: z.string().optional() }
TOOL_RISK: destructive
```
Emits a warning if the current branch has a remote tracking ref (`git log --remotes` check) — amending a pushed commit would require a force push, which is out of scope.

### git_checkout_branch (`checkoutBranch.ts`)
```
git checkout -b <branch>
schema: { branch: z.string() }
```
Returns the branch name on success. If the branch already exists, returns an informational message and does not throw.

### git_push (`push.ts`)
```
git push -u origin HEAD
schema: {}   (always pushes current branch to origin)
TOOL_RISK: destructive
```
`-u` sets the upstream so subsequent pushes need no arguments.

### git_stash (`stash.ts`)
```
git stash [push | pop | list]
schema: { action: z.enum(['push', 'pop', 'list']), message: z.string().optional() }
```
Available to the git agent node (for user-initiated context switching). Not used by `executeGitOps`.

## Test Coverage

New file: `__tests__/agent/gitExecution.test.ts`

### buildGitIntent
- Returns `null` when `plan.gitStep` is null
- Derives `filesToStage` from `editorAppliedFiles` (deduplicates)
- Sets `branch`, `push`, `amend` from `plan.gitStep`

### executeGitOps
- Skips branch step when `gitIntent.branch` is undefined
- Runs `git_checkout_branch` when `gitIntent.branch` is set
- Stages only the specified files
- Runs `git_commit` when `amend=false`
- Runs `git_amend` when `amend=true`
- Skips commit/amend when nothing staged
- Sets `pendingToolCall` when `push=true`
- Does not set `pendingToolCall` when `push=false`
- Records `gitOpResults` for each step

### Routers
- `afterExecuteGitOps` → `'push_approval'` when `pendingToolCall` set
- `afterExecuteGitOps` → `'final'` when `pendingToolCall` null
- `afterPushApproval` → `'tools'` when `toolApproved=true`
- `afterPushApproval` → `'final'` when `toolApproved=false`

### git_amend tool
- Stages files and amends with new message
- Stages files and amends with `--no-edit` when message omitted
- Emits warning when remote tracking ref detected

## What This Does Not Cover

- **PR creation** (`gh pr create`) — separate feature, separate design
- **Merge conflict resolution** — requires a dedicated interrupt flow
- **git rebase / squash** — not triggered by planner today
- **Multi-remote support** — push always targets `origin HEAD`
- **Force push** — `git_amend` on a pushed branch warns but does not force push; user must handle manually
